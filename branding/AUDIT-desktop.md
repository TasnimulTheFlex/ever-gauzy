## Updates and releases

**Automatic update installation is disabled for Base360 app IDs.** Fresh settings default to disabled; persisted settings cannot restart polling, and update strategies cannot check/download an installer for `com.base360.*`. The settings update screen opens this fork's releases for manual installation.

Release lookups are pinned in the shared updater to **TasnimulTheFlex/ever-gauzy**, independent of a stale caller's repo settings. All six Electron publish configurations, environment defaults and version-script repo fallbacks target that fork. The obsolete DigitalOcean strategy delegates to GitHub. These apps must never use an ever-co release feed.

Reason for disabling installs: multiple unsigned products share the same fork release repository and the legacy update manifests do not distinguish products reliably. Before enabling automatic installation, introduce per-product/per-architecture update manifests and configure Base360 signing/verification. Native installer publication does not require automatic updates.

Added `.github/workflows/base360-timer-release.yml`:

- Runs on `vX.Y.Z` tags or manual dispatch with an existing tag; validates the stable version and stamps the Timer package.
- Builds **macOS arm64** (`macos-15`), **macOS x64** (`macos-15-intel`), **Windows x64** and **Linux x64** on GitHub-hosted runners using the existing repository build/Nx pipeline.
- Packages macOS DMG/ZIP, Windows NSIS EXE and Linux AppImage/DEB/tar.gz. Builds first, then uploads the installers to this fork's GitHub Release using `GITHUB_TOKEN` with release-job-only `contents: write`.
- Is restricted to `TasnimulTheFlex/ever-gauzy`. It uses no upstream PAT, signing credentials, private registry credentials or automatic update manifests.
- Replaced the nine old Timer/Desktop/Agent demo/stage/prod release workflows, which depended on upstream infrastructure and destinations. Desktop/Agent packaging scripts remain available; automatic fork releases are provided for Timer only, as requested.
- Repointed the separate server Electron workflows' build metadata/release destinations to the fork and removed their upstream Snap Store publish overrides. These retained workflows still depend on their existing runner/signing setup; only the new Timer workflow is designed as the fork's self-contained release path.

**Signing follow-up:** obtain Apple Developer ID signing and notarization credentials and a Windows certificate or Azure signing profile whose company/publisher is Base360. Current Timer builds are unsigned (macOS may use local ad-hoc signing); OS trust prompts are expected. No releases were triggered, uploaded or pushed during this work.

Runner/config references checked against [GitHub's runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) and [electron-builder v26 macOS options](https://www.electron.build/v26/docs/mac/).
